# User data — Model library and Settings profiles: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One per-user data folder with two parts.
- **The model library:** one surrogate model per Kohn-Sham surface and species set, resolved from the scene, saved automatically and announced when it switches. It survives restarts and crashes, and the Model tab describes the active model.
- **Settings profiles:** named, with a default applied at launch and a reset to factory settings.

Both parts share one atomic-write and lock layer.

**Architecture:**
- A new std-only crate, **`userdata`**, holds the data-folder resolution, atomic writes, file locks, the JSON reader and writer (moved out of `surrogate::sidecar`), FNV-1a and `utc_label`.
- `surrogate` gains the sidecar v4 format, `library::{LibraryKey, Library}` (the index, the leases, corrupt quarantine) and the file-level `sidecar::merge`.
- `providers::surrogate` records history (audit tag, passes, teacher time, dates, revision, coverage) and encodes and decodes v4 behind four new `Trainable` methods.
- `app::worker` replaces the session autosave with key resolution, switching, debounced saves and leases.
- `app::settings` and `app::profiles` hold the settings inventory, the profile JSON and the apply path through the existing controls' commands.
- The chrome (the Model tab info and Library section, File ▸ Profiles, toasts) comes last.
- No physics changes.

**Tech Stack:** Rust, std only. No new external crates: `std::fs::File::try_lock` (Rust 1.89, toolchain 1.99), and a hand-written FNV-1a and civil-date conversion.

**Spec:** `docs/superpowers/specs/2026-10-15-user-data-design.md`; the section numbers below refer to it. Inputs: `docs/superpowers/notes/2026-10-13-m5-user-requests.md` § "Model library: automatic per-scene models" (binding); the user's follow-ups of 2026-10-14 (restart, profiles) as ruled by the controller; the M5 and M6 specs.

## Global Constraints

- **Rule 1:** no per-element data is added. The label's symbols are display data from `units::isotopes::symbol`.
- **Rule 2:** std only, with hand-written JSON, hashing and dates. No `serde`, `dirs`, `chrono` or `fs2`.
- **Rule 3:** atomic units in files and readouts' sources. Å and eV appear only at the UI edge.
- **Rule 5:** `sim` sees bytes and plain records across `Trainable`, never a file format or a path policy.
- **Rule 6:** Task 4 touches the surrogate's store, so `cargo test -p validate --release --test surrogate` must reproduce the M6 handoff's numbers to the printed digits. Nothing else in `validate` changes.
- **Rule 7:** the key cannot see a teacher code change. A future milestone that changes the teacher's Hamiltonian **must rename the teacher** (`ForceProvider::name`), e.g. `Kohn-Sham (GPU, PP)`. Write this into `providers::ks`'s module doc and into `crates/validate/references.md` § Surrogate.
- **Rule 8:** a profile's `run.speed` is steps per tick, never dt.
- **Samples are never discarded silently.** Every save failure is a Log error, a toast and a red line, and the bytes stay in memory until they land.
- **Tests never touch the real user data.** `userdata::default_root()` is called only from `main.rs`, and every test passes a temp directory. Task 5's grep step checks this.
- **One source of truth for factory settings.** `UiState::new` is built from `Settings::factory()` (Task 8).
- **Determinism:** FNV-1a and `{:?}` floats only. `DefaultHasher` is forbidden for anything written to disk.
- Timings (save cost, switch cost) are reported, never asserted.
- **README is kept current** (CLAUDE.md user instruction): Tasks 7 and 9 update it in the same commit. CLAUDE.md's description of the model files ("models autosave per session and save/load as `<scene>.model`") is rewritten in Task 7.
- Commit with `git commit -o -- <paths>` (memory rule: an implementer may share the checkout).

## Review Focus

Each item names the failure and the test that pins it.

1. **F1 Two instances or two workers on one library lose samples or tear the index.**
   - Task 3 `two_handles_share_one_entry_without_losing_samples`: the lease is exclusive, the second handle is read-only, and it acquires once the first drops.
   - Task 3 `concurrent_index_updates_keep_every_entry`: 2 threads × 50 entries on separate handles give 100 entries in a parseable index.
   - Task 5 `a_second_worker_on_a_leased_entry_is_read_only_and_merges_when_the_lease_frees`: the final file holds A's samples plus B's new ones, with no duplicates.
2. **F2 Key drift from float formatting**, or a key that equates surfaces the gate refuses.
   - Task 3 `the_canonical_key_and_its_hash_are_pinned`: the exact text, and the spec §3.3 table of hashes.
   - Task 3 `the_key_is_bit_exact_and_agrees_with_the_provenance_gate`: "0.25", "0.250" and "2.5e-1" give `2d97a5e0204aa194`; +1 ulp gives `69a816e5564c635c`; σ `None` ≡ `Some(h)`; over 12 provenance variants, key equality ⇔ gate equality ∧ equal species; masses never change the key.
3. **F3 A scene switch mid-pass** puts samples in the wrong entry or leaves the pass running.
   - Task 5 `a_key_change_mid_pass_cancels_the_pass_into_the_old_entry`.
   - Task 5 `a_non_key_edit_mid_pass_keeps_the_pass_and_the_entry`.
4. **F4 An autosave racing a refit** writes a half-applied fit, or an older state over a newer one.
   - Task 5 `a_save_holds_the_refit_it_follows_and_saves_are_debounced`: every written file installs cleanly with `model.n_samples ≤ samples`; the header revision is non-decreasing across writes; the number of writes is ≤ ⌈run / save_every⌉ + 2.
5. **F5 A renamed scene file** loses its model, or its sidecar is imported twice.
   - Task 6 `a_renamed_scene_finds_its_model_by_key_and_its_sidecar_imports_once`.
6. **F6 The restart** (user follow-up) loses samples or the fit, refits, or changes trust.
   - Task 7 `a_relaunched_viewer_restores_the_model_without_a_refit`: samples, fit tuple (bit-exact), trusted and reason all equal; refits 0; no pass; the line reads "loaded from the library (last trained …)".
   - Task 7 `a_crash_restores_the_last_debounced_save`.
7. **Silent loss on a failed save.** Task 5 `a_failed_save_keeps_the_model_in_memory_and_says_so`.
8. **P1 A profile from a newer version** is refused, misread, or loses settings.
   - Task 8 `a_newer_profile_applies_known_keys_and_keeps_unknown_ones_on_update`.
9. **P2 A profile naming a grid the GPU cannot fit**, or an invalid grid.
   - Task 9 `a_profile_grid_is_validated_like_apply_grid_and_the_rest_still_applies`: n = 99 and a box too small for water are both refused, while dt still applies.
   - Task 9 `undo_restores_the_previous_settings`: the allocation-failure path ends with Undo.
10. **P3 Switching profile mid-pass** silently cancels a pass.
    - Task 9 `a_profile_that_changes_the_grid_mid_pass_needs_a_second_click`.
    - Task 5's F3 test: where the samples go.
11. **P4 The default profile deleted.**
    - Task 8 `deleting_the_default_profile_clears_the_pointer`.
    - Task 9 `a_deleted_default_profile_launches_factory_settings_and_says_so`.
