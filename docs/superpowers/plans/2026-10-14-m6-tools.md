# M6 — Tools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bonds and molecules read off the electron density (a bond-critical-point test on the internuclear segment against the solver's own isolated-atom promolecule), Hill formulas with structural and trivial names, per-nucleus isotopes with an H₂/D₂ oracle, a FIRE relax tool booked as a tool, a composition/force badge, an input-replay harness that automates the viewer checklist — on top of the deferred refactors: a `providers` crate behind a `Trainable` trait, the two file splits, median-sized automatic passes, the far-drag test at 49³.

**Architecture:** `sim` keeps the `ForceProvider` boundary (now with `sample_density` and `as_trainable`), the driver, and two new pure-f64 modules — `references` (radial isolated-atom densities, the cache, `solve_atom`) and `bonds` (the three-condition detector and union–find components) — plus `relax` (FIRE as a driver mode). The Kohn-Sham and surrogate providers live in the new `providers` crate; the GPU gets one small trilinear line-sampling kernel in `qm-gpu`. `app` gets `names` (formulas, classification, the trivial table), `badge`, `replay` (recorder, parser, replayer, `ui::Action`), and the worker split. Validation in `validate/tests/tools.rs`. UI wiring is the last task, after the redesign branch merges.

**Tech Stack:** Rust; no new crates. Fable for the detector, the references, isotopes, FIRE and the oracles; Opus for the refactor, the kernel, names, replay, sizing and the chrome.

**Spec:** `docs/superpowers/specs/2026-10-14-m6-tools-design.md` (the section numbers below are its). Parent: `docs/superpowers/specs/2026-10-12-atomic-sandbox-design.md` §5, §7, §8, §9. Inputs: the M5 handoff ("Notes for M6", deferred list), the M4 handoff (deferred list), the M2 checklist note.

**Model tags:** **[Fable]** Tasks 3, 5, 6, 7; **[Opus]** Tasks 1, 2, 4, 8, 9, 10. Fable→Opus fallback on dispatch failure (user ruling).

**Branch dependency:** Task 10 (chrome) waits for the UI-redesign branch to merge to main (spec §10); rebase `m6-tools` on main before it. Tasks 1–9 touch `ui.rs` only to add seams under a marked "M6" heading, never to move existing controls.

## Global Constraints

- Rule 1: per-element data are Z and measured isotope mass only. The bond detector's constants (M = 33, ε_⊥ = 0.02, ρ_floor = 1e-2 e/Bohr³, δ = 0.10, R_max = 8 Bohr, dr = h/2, 64 directions) are universal; the promolecule is *solved*, never tabulated; names, symbols, the element ordering and the trivial-name table are display data in `app` only.
- Rule 2: hand-written everything; `rand` only for the sampling pass (unchanged).
- Rule 3: atomic units inside `sim`, `providers`, `qm-gpu`; conversions at the UI edge through `units`.
- Rule 4: f64 on the CPU (references, detector, FIRE); f32 on the grid; the density samples cross as f32 → f64.
- Rule 5: `sim` never learns what computed a density: `sample_density` returns numbers, the detector consumes numbers.
- Rule 6: every existing suite keeps its numbers through the refactor (Task 1's acceptance); new bounds are pinned in `references.md` and never loosened.
- Rule 7: the LiH oracle is asserted bonded and a miss is reported as a finding; ρ_b at h = 0.25 is labelled non-physical for Z ≥ 3.
- Rule 8: FIRE's Δt is its own (`relax::Fire`), never the run's dt; `sim_time` does not advance during a relax.
- One-surface bookkeeping stays exact: FIRE's velocity operations and `SetIsotope`'s ΔK are booked into W like the thermostat's.
- Scene files and presets round-trip byte-identically (A written only when not the most abundant).
- Timings reported, never asserted (R3).

/// ρ at `p` (Bohr) by trilinear interpolation on this grid's points (x fastest); 0 outside [origin, origin + (n−1)h]³.

/// ρ↑ + ρ↓ of `state` at `points` (Bohr): one dispatch over the padded `rho` field with the same weights as `Grid::trilinear`, one readback of points.len() f32.
