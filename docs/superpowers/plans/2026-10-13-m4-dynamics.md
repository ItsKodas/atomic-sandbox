# M4 — Dynamics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the atoms move. Born-Oppenheimer molecular dynamics on the GPU solver — velocity Verlet, temperature from nuclear motion, an optional CSVR thermostat, time controls (play/pause/step/speed/rewind), drag-as-spring, and an energy-drift health readout — validated by the H₂ vibration frequency, NVE energy conservation, and thermostat settling. The viewer becomes a sandbox where you place atoms and watch them vibrate, bond, and heat up.

**Architecture:** New crate `sim` (spec §5, §7): `Nucleus { pos, vel, z, mass }`, `Scene`, the `ForceProvider` trait (`evaluate(&Scene, should_abort) -> Result<ForceResult { energy, forces, stats }, ProviderError>`), a velocity-Verlet `Integrator` with fixed dt, a `Csvr` thermostat, an external uniform acceleration field on `Scene` (gravity hook), and a `Dynamics` driver that owns the scene + provider and runs `steps_per_frame` steps per tick with time-speed ≠ dt, pause/step/rewind (velocity flip), and energy bookkeeping (E_total = KE + E_KS, drift per ps). Two providers: `CpuKs` (wraps `qm::scf` + `qm::forces`) and `GpuKs` (wraps `qm_gpu::GpuSolver::solve_with` + `forces`, warm start, cancellation). The viewer's worker thread runs `Dynamics` instead of one-shot solves; snapshots now carry velocities, T, energies, drift and the trajectory tail. M3's solver prerequisites (Err-not-panic, eigen tol tied to Δρ, cached force buffers, uniform ring) are the first tasks because warm starts and per-step forces become the common case.

**Tech Stack:** Rust; `qm`, `qm-gpu`, `gpu`, `render`, `app` as they are; `rand` (workspace dep, already present) for the CSVR Gaussian draws with a seeded `StdRng`; no new crates.

**Spec:** `docs/superpowers/specs/2026-10-12-atomic-sandbox-design.md` §5.1 (`ForceProvider`, `Scene`), §7 (dynamics loop, time speed ≠ dt, thermostat, energy bookkeeping, electrons, gravity hook, tool interactions as forces, threading, per-step sequence), §8 (time/thermostat controls, readouts), §9.3 (dynamics validation). Handoffs: `docs/superpowers/notes/2026-10-13-m3-handoff.md` (solver prerequisites, f32 floors, egg-box ΣF ≈ 3e-4 Ha/Bohr, path scatter), `2026-10-13-m3-task10-orbital-lag.md`.

**Model tags:** **[Fable]** Tasks 1 (solver prerequisites — numerics), 3 (integrator + energy bookkeeping), 4 (thermostat), 7 (validation); **[Opus]** Tasks 2 (sim crate types + providers), 5 (dynamics driver), 6 (app integration). Fable→Opus fallback on dispatch failure (user ruling).

## Global Constraints

- Atomic units inside `sim` (time unit ≈ 0.0242 fs; dt default 0.25 fs = 10.33 a.u.); masses from `units::isotope_mass_amu` × `AMU_IN_ME` (spec: Z and mass are the only per-element data); conversions to fs/K/eV only at the UI via `units`.
- **Time speed ≠ dt** (spec §7): UI speed changes steps attempted per frame; dt changes only through the explicit dt field with a warning above 0.5 fs.
- Velocity Verlet, fixed dt, symplectic; rewind = flip all velocities. Per-step sequence exactly spec §7: apply commands → half-kick → drift → `evaluate` → half-kick → thermostat → bookkeeping → publish.
- Temperature: T = 2·KE/(k_B·DOF) with COM velocity removed and DOF = 3N − 3 (N ≥ 2; N = 1 → DOF 3 with COM kept — document). Thermostat default OFF (NVE).
- E_total = Σ½mv² + E_KS(from the provider). Drift reported per ps as the primary health indicator; the dynamics suite pins it.
- Forces: the provider's forces are used as-is except for a documented **net-force (COM) correction** option, OFF by default in tests, ON by default in the app, because the egg-box ΣF ≈ 3e-4 Ha/Bohr would otherwise drift the molecule (M3 handoff).
- Tool interactions enter as forces: drag = spring k·(target − pos) with k = 0.5 Ha/Bohr² (document), pin = zero velocity each step, place = at rest; never teleport during a run.
- A failed provider evaluation (`Err`) must not kill the run: the driver pauses, reports, keeps the last good state; the integrator never ingests NaN.
- All physics tests headless; GPU tests release-gated as before; the dynamics suite lives in `validate` with cited references and tolerances that say what they measure (f32 scatter included).

## Review Focus

1. **Energy drift that looks like physics:** a half-kick/drift ordering bug or a thermostat applied inside the Verlet step produces a smooth, plausible energy ramp. Pinned in Task 3 (harmonic oscillator: bounded energy error over 10⁴ steps, time-reversibility to 1e-10) and Task 7 (NVE drift bound on H₂ on the GPU).
2. **dt in the wrong units** (fs vs a.u.) — a 41× error that still "moves". Pinned in Task 3 (oscillator period in a.u. and in fs via `units`).
3. **Provider failure mid-run** (non-finite Gram, cancelled solve): must become a paused run with the last good state, not a panic or a NaN trajectory. Pinned in Task 1 (Err path) and Task 5 (driver test with a provider that fails on step k).
4. **Warm start across steps with orbital lag**: forces carry ~2e-4 Ha/Bohr error at interactive tol unless the eigen tol follows Δρ. Pinned in Task 1 (readback witness + force agreement vs a cold solve) and Task 7.
5. **Rewind and pause must be exact:** rewind after n steps retraces to the start within integrator reversibility (1e-8 on positions over 100 steps) on a symmetric potential; pause/step must not advance time. Pinned in Task 5.
