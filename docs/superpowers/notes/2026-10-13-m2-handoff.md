# M2 handoff — viewer: deferred items and notes for M3/M5

Written 2026-10-13 at the close of M2 (interactive viewer; crates `gpu`, `render`, `app`). Final whole-branch review: ready to merge, no Critical/Important findings; hygiene wave landed in 091e35a. Manual-test tick list: `docs/superpowers/notes/2026-10-13-m2-viewer-checklist.md`.

## What the viewer does (M2)

Window (winit 0.30 + egui 0.36) with an orbit camera; nuclei as impostor spheres with true depth; density as a raymarched volume or isosurface composited against sphere depth; presets H/H₂/He/LiH/H₂O; place / select / drag / delete tools; grid, charge, multiplicity, σ controls; energy/SCF readouts; scene save/load (text format v1); a simulation worker thread wrapping `qm::scf` with command coalescing, warm starts and error isolation; hidden `--screenshot <path> --preset <name>` flag rendering one frame headlessly.

Measured: H₂ at 49³ solves in 5–7 s (CPU, interactive tol 1e-5); H₂O at 57³ in ~116 s. The cloud updates after each drag pause, not during it. That latency is M3's job.

## Contracts M3 must preserve (from the final review)

- `gpu::Volume3D`: `R32Float`, 3D, `TEXTURE_BINDING | COPY_DST | COPY_SRC`, x-fastest `i + nx*(j + ny*k)`, **unpadded**. A GPU solver with 4-cell ghost padding must copy the interior into the unpadded texture (or offset in the shader) — never bind a padded texture to `VolumePass`.
- `render::VolumeUniform`: `box_min`/`box_max` are the first/last **sample** positions (texel centres = `origin` and `origin + (n−1)h`), `scale` is the density divisor (auto-set to `density_max`), `step` in Bohr (`min(0.1, h/2)`).
- `VolumePass::bind(ctx, &Volume3D, &depth_view)` must be re-called whenever the texture object or the depth view is recreated (resize, Lost, grid change). `Painter::rebind` is the hook.
- `app::sim::Snapshot` fields consumed by the panel: `scene`, `grid_n`, `grid_h`, `origin`, `density_max`, `energy`, `iterations`, `max_eigen_residual`, `poisson_residual`, `warnings`, `solve_ms`, `seq`. The `Busy(true) … Snapshot|Error … Busy(false)` event triple and the FIFO + coalesce + shared `Command::apply` lockstep model.
- `CameraUniform` (160 B) / WGSL `Camera` and `VolumeUniform` (48 B) / WGSL `Params` are pinned by compile-time asserts; both shaders reconstruct rays identically (pixel centre, `1 − 2y/h`, `inv_view_proj` near/far), and `depth_to_t` relies on `glam::camera::rh::proj::directx::perspective` (NDC z 0..1).

## Things M3 should change

- `Painter::upload_snapshot` becomes "bind the solver's texture"; `Volume3D::upload` stays for the CPU path and tests.
- `gpu::Volume3D.sampler` is unused: request `Features::FLOAT32_FILTERABLE` when the adapter offers it (the RX 7900 XTX does) and switch `sample_rho` to `textureSampleLevel`; keep manual trilinear as the fallback.
- `INTERACTIVE_TOL` and coalescing numbers are CPU-tuned; add a cancellation point between SCF steps so a drag can abandon a stale geometry (also fixes the `run_app` panic-path join).
- The M1 handoff's items still apply: analytic V_nuc on the GPU (not Poisson at σ = h); validate GPU vs CPU at fixed σ; multigrid at ≳ 101³.

## Deferred minors (ride to M3/M5)

- **Transfer function (UX, first thing a user notices):** auto-scale to ρ_max hides the H lobes in H₂O (O core is 26× denser); and at opacity 2.0 the H₂ cloud swallows its own nuclei. Options: percentile-based `scale` (99.5th), a log-type transfer `s = ln(1+k·r)/ln(1+k)`, lower default opacity, or a minimum sphere visibility. Decide when M3 makes the density live.
- Tools (M5): keep the grab offset on drag (nucleus snaps to cursor by up to one radius); clamp `place_point`/`drag_point` to the grid box and draw the box outline (at default zoom the visible area exceeds the box; `qm` has no out-of-box guard); reset mouse state on `Focused(false)`; zero-nucleus scene → publish an empty snapshot instead of a red error; `DragValue` clamp sends hidden `SetCharge` after deletions (benign auto-correct — document); scene off-centre vs the free area (offset camera target by half the panel width); spec §7 drag-as-spring replaces `MoveNucleus` teleport in M4.
- `app`: `run_app` `Err`/panic path still drops and joins the worker (startup-only); `Drop` could send `Shutdown` without joining; doubled "solver panicked" fallback text; multiplicity "auto" toggle sends a needless `SetMultiplicity`; `Outdated`-retry could storm if a visible window kept reporting `Occluded` (not observed on Windows/Vulkan).
- `render`/`gpu`: `sphere_behind_the_volume_is_tinted` doesn't exercise blending (add a mid-opacity variant); slab test NaN on an exactly axis-aligned centre pixel; `read_back`/`read_rgba` are blocking test helpers (doc); `layout_is_x_fastest` redundant; `Volume3D::new` doesn't validate dims; `Renderer::new` double `set_params`; overlay pass opened with no volume.
- **Input-replay harness (recommended for M3/M5):** drive `App::handle_input`/`on_left_press`/`on_motion` with synthetic `WindowEvent`s against `Headless` through `Painter`/`Viewer` (already window-independent) and assert on pixels/state: orbit/pan sign conventions, zoom floor, Place lands on the focus plane and sends one `AddNucleus`, Select picks the nearer of two overlapping spheres via the pixel path, drag plane fixed + `MoveNucleus` per motion, release over the panel ends the drag, egui-consumed press doesn't orbit, Delete with/without a focused text field, `Resized` re-binds depth, 0×0 draws nothing, `Error` keeps the previous density, `SetGrid` recreates the volume, screenshot path end to end (release-only).
- Hygiene: workspace `cargo clippy` + `cargo fmt` pass (13 warnings in `qm` from M1) before M3 starts in earnest.
