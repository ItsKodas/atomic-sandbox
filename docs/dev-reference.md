## Rule 5's history

- (Since M6 Task 1 the M5 exception, ruling S2, is closed: `sim` keeps the `ForceProvider` and `Trainable` traits and their data types and depends on `units` and `gpu` only — `gpu` for the display texture handle; the providers — `CpuKs`, `GpuKs`, `SurrogateKs` and its sampling pass — live in the `providers` crate; the driver and the worker reach a provider that learns only through `ForceProvider::as_trainable`, and nothing downcasts a provider — the `Any` accessor is gone, review S4.)

## Crates

- Crates: `units`, `qm` (CPU reference), `qm-gpu`, `gpu`, `render`, `sim` (scene, integrator, thermostat, the `Dynamics` driver, relax; the `ForceProvider`/`Trainable` boundary), `providers` (the Kohn-Sham adapters `ks.rs`; the surrogate provider in `surrogate/{mod,policy,trust,quarantine,audit,store}.rs` — the decision list is `mod.rs`'s module doc; the sampling pass in `sampling/`), `surrogate` (the model: descriptors, basis, Bayesian fit, sidecar), `app` (the viewer; its solver worker in `src/worker/{mod,commands,model,autosave,tests}.rs`, `app::sim` kept as a re-export path; the 2D molecule builder in `src/builder/{mod,chem,embed,ui}.rs` — File ▸ Builder…, spec `docs/superpowers/specs/2026-10-20-molecule-builder-design.md`; `chem.rs` is the only home of its valence and covalent-radius tables, a starting-geometry aid under the user's rule-1 sign-off (spec §3) that never reaches `sim`/`qm`/`providers`; tests `cargo test -p app --release --bin app -- builder::`, seconds, CPU; the hand-off is `ui::Action::Builder`, recorded as `# not replayable: builder`), `validate`.

## Build, run and the app's defaults

- Build: `cargo build --workspace`. App: `cargo run -p app --release [-- --backend gpu|cpu] [--preset empty|h|h2|he|lih|h2o|h2s|hcl|ph3|sih4] [--quality fast|balanced|accurate|precise] [--ionic none|cores|accepted|all]` (always release; `start.bat` / `build.bat` at the repo root build incrementally in release and launch; the default grid is **Accurate**, h = σ = 0.15 Bohr with the preset's box kept — 81³ for the 12 Bohr presets, 95³ for lih/h2o — via `app::quality`; Scene ▸ Quality switches Fast 0.30 / Balanced 0.25 / Accurate 0.15 / Precise 0.10 / Custom; a `--scene` file keeps its grid; `--backend cpu` without `--quality`/`--scene` loads Balanced (an 81³ CPU step ≈ 40 s, uncancellable); under the `cores` policy (`--ionic cores`) or the default `accepted` (O is pseudised there too) a preset with N, O, F or Ne is then refused at Balanced (h_req 0.20 / 0.15) — on the CPU pass `--quality accurate` or `--ionic none`; a GPU memory guard (`providers::gpu_footprint_bytes` with `qm_gpu::grid::GHOST` padding, `GpuKs::with_vram_budget`, budget `quality::vram_budget`: `ATOMIC_SANDBOX_VRAM_GB`, else half the card's largest device-local heap when the adapter reports it — `gpu::GpuContext::device_local_memory_bytes`, Vulkan only, set in `Viewer::start` via `quality::set_adapter_memory`; 12.9 GB on the RX 7900 XTX —, else `quality::VRAM_BUDGET_GB` = 12 GB) refuses scenes over it, the refusal naming the budget and its source; `Scene::preset` itself is still the file as written (49³/57³ × 0.25), which the worker tests use, and `scene::h2_r16` is the old R = 1.6 Bohr h2 for tests pinned to it; `empty` = the default cell with no nuclei: the driver answers it without the provider (`sim::nothing_to_solve`) — E = 0, no forces, no density — Play is accepted but time does not advance, estimated mode needs no model; `sim::dynamics` "The empty scene"; temperatures display in K, °C or °F — Physics ▸ Thermostat, conversions in `units`, the simulation stays in kelvin). The default solver backend is the GPU (`qm-gpu` on the window's device; the density texture is bound by the renderer without a CPU copy, and a newer edit abandons the solve in flight at the next SCF step); the panel's "solver" radio switches to the CPU reference (`qm::scf`, uncancellable) and back by re-spawning the worker with the current scene. Since M4 the worker runs `sim::Dynamics`: the app starts paused on H₂ at 1.45 Bohr (this solver's σ → 0 LSDA bond length; under the default `Accepted` policy H is pseudised and the minimum at h = 0.15 is 1.434 Bohr, so it barely vibrates — under all-electron, or without a GPU, the smearing moves the minimum out to 1.60 Bohr at σ = h = 0.15, so it vibrates); Space / the Play button starts Born-Oppenheimer MD, speed = steps per tick (never dt — rule 8), measured fs/s shown; Pause and scene edits (teleport/add/remove/ReplaceScene/backend/grid) abort the solve in flight, drag moves and the drag pull (the wheel while dragging, `SetDragForce`) never do (they only change the spring). Hidden `--screenshot <png> [--preset p] [--backend b] [--play-ms n] [--estimated] [--sample] [--speed n] [--audit n] [--size <w>x<h>] [--ui "<k=v;…>"]` plays for n ms before capturing (`--sample` runs the default sampling pass first; the frame defaults to 1400×900 since the UI redesign; `--ui` keys: `menu`, `tab` (`activity` too), `wait=model` (a fitted model, trusted or not), `training=open` (the Activity tab's Training section, waits for its views), `plan=quick|gentle|standard|hot`, `dock=closed`, `select`, `tool`, `element`, `cursor=x,y`, `search`, `thermostat`, `opacity`, `wait=sampling`, `drag=<i>` (a posed Select-drag: the pull label by the cursor), `pull=<Ha/Bohr>`, `ptable=<query>` (opens the periodic table with that search), `ghost=on|off` and `wait=nudge|scan|burst` (the training ghost, `app::ghost`: during a sampling pass the view draws the geometry the pass is solving — `sim::PassGhost` in `DynSnapshot::ghost`, `Trainable::pass_ghost` — instead of the scene; View ▸ Display aids ▸ show what training is solving, display only), `names=common|stoichiometric|hydride|formula` (the molecule name style), `trails=on|off`, `trail_fs=<fs>`, `trail_opacity=<0-100>` (View ▸ Display aids ▸ Trails: a fading line behind each atom, display only, set before the play so the history is collected), `wait=bonds` (shoots once the bond graph is in: ≈ 100 s for `h2o`, the O reference), `wait=relax` (relaxes with FIRE first and prints a "relax summary" line with the distances and angles; with `wait=bonds` the graph is the relaxed geometry's) — they pose the chrome for the docs screenshots). One-shot solve times, RX 7900 XTX (after M3 Task 10): H₂ 49³ ~0.2 s (warm ~0.1 s), H₂ 81³ (the default since 2026-10-14) 0.53 s cold / 0.28 s warm (`validate --test quality`, report-only), H₂O 57³ ~1.8 s (warm ~1.0 s), H₂O 97³ ~3.6 s (warm ~1.8 s) at the validate suite's tol 1e-6 (CPU: H₂ ~6 s, H₂O 57³ ~2 min). The render thread is not blocked by a running solve (frame p95 ≈ 6 ms during a 97³ solve). Since M5 the solver radio has a third option, **estimated**: `providers::SurrogateKs` (crate `surrogate` — a linear ACE-style potential fitted to this solver's own energies/forces, Bayesian uncertainty, DFT fallback + active learning, background audits) wraps the current teacher; with no model the window waits for Start sampling (since 2026-10-19 the window sends `EnsureModel { auto_pass: false }`; the screenshot/replay harness keeps the automatic pass, `Viewer::auto_pass`), and the harness runs a sampling pass (H₂ 49³ ≈ 40 s, 273 solves — a few minutes at the default 81³; a pass whose trust floor exceeds ~2 min at the scene's first solve asks first, and the automatic pass is shrunk to ~2 min after its first three solves from their median); the surrogate's own teacher — pass, fallbacks, auditor — solves at `SAMPLE_TOL` 1e-6 (labels are permanent; measured: no SCF-lag penalty on the GPU teacher), the DFT display backends keep `INTERACTIVE_TOL` 1e-5, and a model file saved at another tolerance is refused on load; models autosave per session and save/load as `<scene>.model`. Rates (H₂, RX 7900 XTX): the worker test measures ≈ 1.6e5 steps/s (≈ 40 000 fs/s) with background audits every 2000; the headless validate suite 2.4e5 steps/s with audits off; DFT ≈ 3 fs/s; at the top speed (`MAX_SPEED`, 10 000 steps per tick since 2026-10-20; 1000 before) the background auditor saturates (one audit per teacher solve). Flags: `--backend estimated` / `--estimated`, `--sample` (run the default pass headlessly first), `--speed n`, `--audit n`; M5b start-up settings (window and screenshot): `--scene <file>`, `--walls <Bohr>` (the half-width: the app's container walls are **on by default** since 2026-10-14 at `ui::default_wall_half_width`, 1.5 Bohr inside the cell's face — 4.5 Bohr at 49³ × 0.25; `sim::Dynamics` itself defaults to no walls, so the validate suites stay unconfined), `--no-walls` (start with them off), `--quality <level>`, `--draft`, `--cloud-refresh <s>` (the screenshot's play prints a "play summary" line: farthest coordinate, E-conserved spread, side densities, draft banners). The policy constants and their justifications: `crates/validate/references.md` "Surrogate (M5)" table; the decision list: `crates/providers/src/surrogate/mod.rs` module doc. `.claude/launch.json` has the plain run command as `atomic-sandbox`.

## Viewer manual checklist and input replay

- Viewer manual checklist (run after UI/render changes): Task 7, Step 5 of `docs/superpowers/plans/2026-10-13-m2-viewer.md`. Which items were verified in a window, which only by code reading, and (since M6 Task 8) which run as replay scripts: `docs/superpowers/notes/2026-10-13-m2-viewer-checklist.md` (its "M6 Task 8" section maps each script to the items it covers and lists what stays manual).
- Input replay (M6 Task 8, `crates/app/src/replay.rs` module doc = the format): the 3D view's mouse and keys have **one path**, `Viewer::input(&replay::Event, consumed)` (the window converts winit events with `replay::from_winit`; picks use the snapshot mirror, never `shown_scene`), and the chrome's controls go through `Viewer::apply(ui::Action)` = the same `ui::actions::apply` as a click (no second action type; `Action::describe`/`parse` are the script words). Cursor positions are **view coordinates** (offset from the viewport rect's centre in half its height: invariant to window size and dock state for a vertical-fov camera; orbit is per pixel, so replays lay out at the script's `view` size). `--record <file>` (window) writes events, chrome actions (`Viewer::chrome_actions`), `wait ms` for gaps > 50 ms and `wait idle` on idle edges; `--replay <file> [--preset p] [--backend b] [--screenshot png] [--size WxH]` runs headlessly through the screenshot harness (`screenshot::Shot`), exit 1 on the first failed `expect`. `wait idle` needs a snapshot that has seen every command (`Snapshot::commands` == `Viewer::commands_sent`), no relax running, no bond reference pending; dynamics advance only by `wait steps`/`wait fs` (relative). Scripts: `crates/app/replays/*.replay` — each pins the grid and walls it was written for (`action quality balanced`, `action walls off 4.5`, and `scene h2_r16.scene` for the R = 1.6 Bohr H₂; `replays_pass` refuses a script without the two pins, and `--record` writes the start's quality and walls on or off), so the app's defaults (Accurate, walls on) never move a replay —, all run by `replays_pass` in `cargo test -p app --release` (GPU, ≈ 3 min: the two water scripts' O references ≈ 2 min, the surrogate's pass ≈ 45 s). A recorded action without a script form (Apply grid, file save/load, Sample, the offered pass) is written as `# not replayable: <kind>` with a stderr note; the replayer skips saves with a warning and refuses the rest. `--scene` is recorded as a `scene <path>` line; `mark` sets the baseline of the since-mark expectations (`max-dist`, `fallbacks`, `new-samples`, `new-epochs`); `wait source S` polls. Scripts were authored from the default camera's geometry (no interactive window was available to record them), not recorded by hand. The user-data milestone must give `--record`/`--replay` a temporary data root (`--data-dir`).

## Test suites

- Viewer tests: `cargo test -p app --release` (the Activity tab's UI tests are `ui::tests::activity_*`; `surrogate_far_drag_recovers.replay` also expects `solve-log 1` and `counters`; `activity_overhead_is_reported` and `the_activity_tab_frame_cost_is_reported` print the overhead and the frame cost, never assert them; ~10 min after activity Tasks 6–9 — 594 s, 253 tests + 2 ignored at `--test-threads 4`; it was 807 s (189 tests, a loaded machine) at activity Task 5 and 591 s in M6 Task 8's fix-round-1 run of record and 632 s (170 tests) after the second merge of `main` — of which ≈ 3 min are the ten replay scripts in `replays_pass`; the GPU tests are serialised) runs the worker tests (`crates/app/src/worker/tests.rs`) (dynamics driver through the worker: play/pause/step, drag flood, provider failure, warm-start witness; estimated mode: sampling pass → trust → play rate, fallback on a far teleport, sidecar save/load, autosave ownership, pacing under a command flood; main's empty-preset, Accurate-default and walls-default tests, the viewer ones pinned to the preset files' grids and `scene::h2_r16` through `viewer::tests::pinned`) (real SCF solves, both backends; the GPU ones skip without an adapter). The same command also runs `crates/app/tests/surface_reconfigure.rs` (Windows, ~3 s): a thread submits on the shared device while a hidden window's surface is reconfigured 100 times; `SurfaceState::resize` must return `Err` (wgpu 30's `GpuWaitTimeout` validation error, captured in a thread-local error scope) instead of panicking, and the viewer retries on the next redraw.
- Unit tests: `cargo test -p units -p qm --release` (~75 s); `cargo test -p sim --release` (seconds, 88 tests: integrator, CSVR, relax, bonds, references, the driver on analytic providers incl. the drag pull, a pull change during a relax and the empty scene), `cargo test -p providers --release` (~70 s, 90 tests + 3 ignored since M6 Task 11's policy tests: the empty scene and the GPU memory guard (`gpu_footprint_bytes`, `GHOST == 4`) since the second merge of `main`; the Kohn-Sham adapters, the surrogate policy and sampling tests — through `Dynamics` too —, a few GPU provider round trips) and `cargo test -p surrogate --release` (seconds; basis, descriptors, fit, sidecar). The `qm` SCF/forces tests are release-only in practice (debug is far too slow).
- Oracle suite: `cargo test -p validate --release` runs ALL validate binaries (oracles ~31 min + gpu_vs_cpu + dynamics + surrogate + tools; `surrogate_perf` is ignored); the σ → 0 oracles alone are `--test oracles` (H, He and H₂). The Li oracle is `#[ignore]`d as a documented limitation (see `li_atom_lsda` in `crates/validate/tests/oracles.rs`).
- Surrogate suite (M5): `cargo test -p validate --release --test surrogate` (~12–17 min on the GPU since M6 Task 11; H₂ frequency vs the M4 DFT-MD pin, fresh-point surface reproduction, 10 ps NVE on the model, OOD fallback rules, H₃⁺ tier at 49³, active learning from no model, and Task 11's stuck-then-escape repro `the_stuck_escape_repro_is_answered_honestly` — H₂ plus the stretched tail sample, one H added after a 4000 K run, an NVE run and a strict hot run with walls, every 4th model answer checked against DFT; `box_rule_on_the_default_and_accurate_grids` is an ignored measurement; `SURROGATE_SEED` / `REPRO_STEPS` overrides). Task 11's rules (`crates/providers/src/surrogate/mod.rs` module doc, `references.md` "Surrogate (M5)" table): the teacher's inside-cell check under the surrogate, a lone atom (rule 5a: no neighbour within r_cut in a scene of two or more) is never answered, novelty (rule 5d: feature directions the training data never spanned), the extrapolation grade (rule 5e: MaxVol active set, γ_max 2), audits judge forces as well as energy, and class-wise (pair / many-body) leave-one-out trust (rule 4b; the max LOO error per class — a documented, deliberately cautious limitation). Surrogate/provider/policy changes must pass it (rule 6).
- Dynamics suite (M4): `cargo test -p validate --release --test dynamics` (~6 min solo on the GPU; H₂ vibration vs the curvature of its own σ = 0.25 surface, 0.5 ps NVE drift, CSVR on H₃⁺, GPU rewind; the H₂O-preset test is `#[ignore]`d as a documented resolution limit; `DYNAMICS_SEED` overrides the thermostat seed). Dynamics changes must pass it (rule 6).
- Tools suite (M6): `cargo test -p validate --release --test tools` (9.7 min measured with two viewer windows sharing the GPU; an earlier, slightly smaller version took 3.0 min on a quiet one; bonds on the real surface — H₂ with the 12-placement noise check behind δ/ε_⊥, He₂ `NotAccumulated` with its margins, the H₃⁺ ring via the march, water's two O–H and no H–H (condition 4, attribution), HeH⁺ and LiH reported; the H₂/D₂ Verlet-corrected mass ratio; FIRE vs the quench by energy with the Hessian's k_min; the surrogate relax verified by its teacher). Bond/relax/isotope changes must pass it (rule 6).
- Partial charges (`sim::charges`, Hirshfeld, display only — computed in the driver's `refresh_bonds` from the bond graph's density and references, and from estimated mode's side densities by the worker; `ForceProvider::valence_charges`): `cargo test -p validate --release --test charges` (CPU, ≈ 11 min: H₂ neutral, LiH Li δ+, HeH⁺ Σq = +1; numbers in `references.md` "Partial charges").
- GPU-vs-CPU suite (M3): `cargo test -p validate --release --test gpu_vs_cpu` (~3.5 min; energies, forces and the H₂ curve shape at **fixed σ = h = 0.25**, 49³, plus a timing table written to the gitignored `crates/validate/last-run-gpu.md`). Skips cleanly without a GPU adapter. Why fixed σ and not the σ → 0 oracles: `crates/validate/tests/gpu_vs_cpu.rs` module doc / `references.md` "GPU vs CPU at fixed σ".
- `cargo test --workspace` (debug) skips the oracles by design: they are `#[cfg_attr(debug_assertions, ignore)]` and run only under `--release`.

## SCF stall stop

- SCF stall stop (both solvers, `qm::scf` module doc "The stall stop"): a solve whose best Δρ has not halved within `ScfSettings::stall_window` = `qm::SCF_STALL_WINDOW` = 50 iterations, while that best is still ≥ `qm::SCF_STALL_LEVEL_PER_ELECTRON` (1e-3) × the electrons the solve carries (the level gate: stretched H₂ converges after 150-iteration plateaus far below it), ends with `QmError::ScfStalled` / `SolverError::ScfStalled` (a warm one is retried cold like `ScfNotConverged`, R15); checked after the convergence test, so converged results are bitwise unchanged. W's measurement: `cargo test -p providers --release scf_stall_measurement -- --ignored --nocapture`, `references.md` "SCF stall stop". `scf_observed` / `GpuSolver::solve_observed` feed `ActivityProbe::scf_iteration` (Δρ, the Harris–Foulkes energy, the countdown; on the GPU it rides on the Δρ readback); the Activity tab words a pass as **samples** ("Sample 42 of 158") and SCF rounds as **iterations** ("iteration 37 / 200"), and the solve log shows each solve's iterations and end (converged / stalled / cap). In a pass a stretched scan point that fails skips its scan's further-out points.
